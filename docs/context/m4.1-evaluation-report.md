## 17. Post-closure correctness amendment

closure. It does not rewrite that historical evaluation as though the later
correction were already present. The original evaluation closure was recorded
in commit `0ee0524` (`test(context): close m4.1 evaluation`). A later narrow
audit identified a real fallback gap at the optimized pre-dispatch compilation
boundary. Commit `a9ff809` (`fix(context): fallback on optimized compilation
failure`) corrected that gap.

- An optimization-specific candidate compilation or validation failure falls
  back to the unchanged original baseline exactly once.
- A shared prerequisite failure propagates with no fallback.
- An unrelated or programming exception propagates with no fallback.
- An optimized dispatch failure does not retry the baseline.
- There is no broad `Exception` catch and no exception-text matching.
- No partial optimized dispatch occurs.
- `stage_request` telemetry semantics remain unchanged.
- Lifecycle behavior remains unchanged.

nor implements M4.2, and it does not change M4.2 planning authority.
