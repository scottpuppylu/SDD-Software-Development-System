# M4.2 Persistence Decision v1

Status: **PLANNING AUTHORITY INPUT ONLY**

This document resolves M4.2 Blocker 10 for planning only. It does not authorize implementation.

## 1. Decision and authority boundary

M4.2 machine evaluation metadata is non-persistent. Machine-generated evaluation state remains ephemeral, in-memory, evaluation-local, and test-local where later authorized implementation tests require it. It MUST NOT become runtime durable state.

Persistence is not authorized by this decision. Any future persistence or telemetry-schema change requires separate, explicit project authority before implementation.

## 2. Forbidden persistence targets

M4.2 machine evaluation metadata MUST NOT be persisted into:

- `.sdd` state;
- lifecycle state;
- run records;
- an evidence runtime registry;
- checkpoint state;
- a context cache;
- a baseline registry;
- a provider/session registry;
- telemetry fields or events beyond the existing schema `1.0.4`;
- repository runtime-generated JSON, JSONL, or YAML persistence; or
- any cross-run trust store.

None of these targets may be introduced or extended for M4.2 unless separate future authority explicitly authorizes that exact persistence or schema change.

## 3. Human-readable documentation exception

Future M4.2 implementation closure may commit the following bounded human-readable report:

```text
docs/context/m4.2-evaluation-report.md
```

That report is documentation evidence and manually reviewed, committed project history. It is NOT machine runtime state, a cache, baseline authority, telemetry persistence, or lifecycle authority. This decision does not create the report and does not authorize runtime machinery to generate or trust it.

## 4. Ephemeral lifetime

Machine evaluation metadata may live no longer than the current controlled evaluation execution, process/evaluation scope, or test case/suite scope where applicable. It MUST NOT be trusted across independent executions.

Restarting or disabling optimization requires no migration, cleanup, repair, cache invalidation, or persistence reconciliation.

## 5. Cross-run trust

Cross-run evaluation-state trust is forbidden. Every future execution must derive its current evaluation facts from current fresh inputs and current exact assembly rather than trusting previous machine state.

## 6. Telemetry boundary

The telemetry schema remains exactly `1.0.4`. M4.2 does not add new fields, event types, metadata keys, reuse counters, delta records, baseline identifiers, or evaluation-status persistence.

Schema `1.0.4` has closed vocabularies and closed metadata where specified; producers cannot locally extend those surfaces. Any M4.2 telemetry addition or other schema change requires a separate explicit schema-version authority decision before implementation.

## 7. Security and data minimization

Machine-local temporary data may contain only what is necessary for the controlled evaluation and MUST NOT gain durability merely for convenience.

Committed human-readable reports must remain bounded and MUST NOT contain raw prompts, raw provider payloads, raw authority or component bodies, provider transcripts, stdout/stderr, secrets, environment dumps, or unsanitized absolute paths.

This decision does not design or authorize encryption, retention services, databases, cleanup daemons, or equivalent persistence infrastructure.

## 8. Implementation consequence

Approval of this Blocker 10 decision would resolve all ten M4.2 blockers for planning. Resolving all planning blockers is not implementation authorization.

Implementation still requires separate project-authority approval. Implementation slicing and order also require authorization. No production or test changes are authorized by this document. M4.2 implementation is neither ready nor started; its status remains `BLOCKED`, with the remaining block being project-authority implementation authorization rather than an unresolved planning blocker.

Blocker 10 resolution closes planning only. Implementation remains blocked, and separate project-authority approval is required before production or test work. No code, tests, telemetry schema, persistence, cache, lifecycle, or `.sdd` changes are authorized by this decision.
