## 2. Inventory boundary and counting rule

The actual assembly boundary is `StageRunner.build_request()` -> `StageExecutionRequest` -> `build_baseline_package()` / `build_optimized_package()`. Dispatch passes `CompiledContextPackage.request` to the executor; the manifest entries describe the request decomposition, but are not separately rendered into executor input. For an external command executor, the provider-facing payload is the JSON serialization of the selected request.

An inventoried component is one distinct fixed request slot or one distinct currently producible keyed entry. This yields **55 current components**: 2 fixed context components, 19 artifact entries, 22 configured semantic-input entries, 8 runtime-input entries, and 4 metadata entries. The dictionaries remain structurally open to caller-supplied keys; any unlisted key is not invented here and must be treated as an unenumerated `UNKNOWN` or `MIXED_AUTHORITY` input with `FAIL_CLOSED_EXACT` treatment.

Compiler behavior common to all entries:

- Fixed entries are ordered first, then artifact, semantic, and runtime dictionaries are sorted by UTF-8 key bytes, followed by four fixed metadata entries.
- Dictionary keys become hex-encoded component-ID suffixes. Duplicate keys cannot survive Python dictionary construction; later assignment replaces the earlier value before assembly. Duplicate component IDs are rejected by package validation.
- Strings are preserved as values and canonically measured as UTF-8. Other supported values are canonical compact JSON for measurement. Exact entries retain the same source/result body. `None` is distinguished from absent only for the explicitly absent-capable fixed slots described below.
- Every assembled entry is provider-facing through the selected request. An absent stage-instructions or core-question value remains a compiled manifest entry and a JSON `null` request field.
- Baseline compilation is exact. Current optimized compilation can transform only `runtime_inputs["GIT_HISTORY"]` under the separately approved M4.1 policy; this observation grants no M4.2 selection authority.
